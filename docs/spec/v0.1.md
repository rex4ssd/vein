# ctx v0.1 — Technical Spec (RFC)

> Status: **Draft**
> Author: R (Rex) + Claude
> Date: 2026-05-26
> Target: Phase 0 minimal kernel，dogfood on Lode 1 個月

---

## 1. Problem Statement

LLM 協作的三個真實痛點（同時打中個人開發者、團隊、企業）：

### 1.1 Context window 浪費

當前 frontier LLM context 雖大（200K~1M token），但：
- **per-turn payload 才是真瓶頸**：autocompact 才剛壓縮，3 個 turn 內又被大檔讀爆
- 每個 session 重新讀同樣的 `architecture.md` / `changelog.md` / source file
- token cost 線性累積，重複內容拿不到折扣

### 1.2 Multi-LLM 重複工

開發者同時用 Claude（推理）、Gemini（長 context）、GPT（generic）、local（隱私）：
- 每個 LLM 各自 onboard 一次
- 沒有共用的「專案記憶」格式
- 換工具像換新員工

### 1.3 缺 portable 的 AI memory

`CLAUDE.md` / `.cursor/rules` / `.continue/config` 都是 vendor-specific 解法：
- 換 IDE / 換 model client 就丟
- 沒有 well-known 格式像 `.git/` 那樣跨工具共用
- 個人慢慢累積的 prompting know-how 黏在 chat history 裡，沒沉澱

## 2. Goals / Non-Goals

### Goals (v0.1 must have)

| # | Goal | 驗收標準 |
|---|---|---|
| G1 | 把 per-turn LLM context payload 降 ≥ 60% | dogfood on Lode 一個月，比較 before/after |
| G2 | Local-first，敏感內容不離本機 | embedding / digest / cache 全在 `.ctx/` |
| G3 | Model-agnostic | 任何 LLM client 透過剪貼簿或 stdout 拿 brief 就能用 |
| G4 | Portable | `.ctx/` 可 commit、可 rsync、可跨 model 換 |
| G5 | Simple | core kernel ≤ 800 行 Python；新使用者 5 分鐘上手 |

### Non-Goals (v0.1 won't do)

| # | Non-Goal | 為什麼不做 |
|---|---|---|
| N1 | MCP server | Phase 0.3 才加，先驗證 CLI 流程 |
| N2 | Web UI | Phase 0.4。Lode 之後當 visual frontend |
| N3 | Multi-project sync / cloud | scope creep，先單機 |
| N4 | Framework abstraction（plugin system） | 過早抽象。先寫死 ollama，看到第二個 use case 再抽 |
| N5 | 即時對話（chat REPL） | ctx 不是 chat client，是 context 預處理器 |
| N6 | 自動 commit `.ctx/` 到 git | user 自己決定要不要 commit |

## 3. Mental Model

> `.ctx/` is to AI collaboration what `.git/` is to version control.

|  | `.git/` | `.ctx/` |
|---|---|---|
| 管什麼 | source code 版本 | LLM 上下文 / digest / memory |
| Per-project | yes | yes |
| Local-first | yes | yes |
| Portable | yes（clone/push） | yes（rsync/commit） |
| Tool-agnostic | yes（git CLI、各 IDE） | yes（ctx CLI、未來 MCP、各 LLM client） |
| 核心動詞 | commit / log / diff | index / digest / ask |

關鍵差異：**git 存的是 ground truth；ctx 存的是 derived view**（永遠可從原始檔重建）。所以 `.ctx/cache/` 進 `.gitignore`，`.ctx/config.yaml` 進 git。

## 4. Architecture

```
        ┌─────────────────────────────────────┐
        │  User                                │
        └──────────────┬──────────────────────┘
                       │ ctx ask "..."
                       ▼
        ┌─────────────────────────────────────┐
        │  ctx CLI (Python)                    │
        │   - retrieve relevant chunks          │
        │   - call local AI for digest          │
        │   - emit brief (stdout / pbcopy)      │
        └───────┬───────────────┬─────────────┘
                │               │
                ▼               ▼
        ┌──────────────┐  ┌──────────────────┐
        │ .ctx/        │  │ ollama (local)   │
        │  index/      │  │  - embedding      │
        │  digests/    │  │  - digest LLM     │
        │  cache/      │  │  - reasoning LLM  │
        └──────────────┘  └──────────────────┘
                │
                │  brief 進剪貼簿
                ▼
        ┌─────────────────────────────────────┐
        │  Cloud LLM (Claude / Gemini / GPT)  │
        │  收到 ≤ 2K token brief 開工          │
        └─────────────────────────────────────┘
```

**Data flow：** raw files → chunks → embeddings → (query) → top-k chunks → local AI digest → brief → cloud LLM.

## 5. `.ctx/` Folder Schema

```
.ctx/
├── config.yaml             # 模型設定、include/exclude glob、digest budget
├── index/
│   ├── chunks.jsonl        # 每行一個 chunk: {id, file, range, text, hash}
│   ├── embeddings.db       # sqlite-vec：chunk_id → vector
│   └── manifest.json       # file path → mtime + chunk_ids，做 incremental
├── digests/
│   ├── weekly/
│   │   └── 2026-W21.md     # 預算好的週報（local AI 跑 cron 產出）
│   └── topics/
│       └── search.md       # 「search 相關」的常駐 digest
├── cache/
│   ├── ask/                # query hash → digest 結果，TTL 7 天
│   └── ollama/             # ollama call 結果 cache
├── memory/
│   └── sessions.jsonl      # 每個 ctx ask 的 query + brief（給未來分析）
└── .gitignore              # cache/, index/embeddings.db
```

### config.yaml 範例

```yaml
version: 0.1

include:
  - "**/*.md"
  - "src/**/*.py"
  - "src/**/*.ts"
  - "src-tauri/src/**/*.rs"

exclude:
  - "**/node_modules/**"
  - "**/target/**"
  - "**/.git/**"
  - "**/dist/**"

chunking:
  strategy: fixed_token         # v0.1 只支援 fixed_token
  size: 400
  overlap: 50

models:
  embedding: nomic-embed-text   # 透過 ollama
  digest_small: qwen2.5-coder:7b    # input < 5K token
  digest_large: deepseek-r1:14b     # input ≥ 5K token
  router: llama3.2:3b           # 決定要不要 escalate

ask:
  top_k: 12                     # retrieval 抓幾個 chunk
  digest_budget_tokens: 2000    # 最終 brief 上限
  cache_ttl_days: 7

ollama:
  base_url: http://localhost:11434
  timeout_seconds: 120
```

## 6. CLI Commands

| Command | 動作 | 說明 |
|---|---|---|
| `ctx init` | 在當前目錄建 `.ctx/` + 預設 config | idempotent |
| `ctx index [--incremental]` | 掃檔、chunk、embed | 預設 incremental，`--full` 強制重建 |
| `ctx ask "問題" [--paste] [--no-cache]` | retrieval → digest → brief | `--paste` 同時複製到剪貼簿 |
| `ctx status` | 印 `.ctx/` 狀態（檔數、chunk 數、最後 index 時間） | 健康檢查 |
| `ctx brief --recent 7d` | 從 changelog / git log / digests 產出近期摘要 | 給新 session onboard 用 |
| `ctx config get/set <key> [value]` | 管理 config | shortcut，不想叫人手 edit yaml |

## 7. Model Routing

| Model | 角色 | 何時用 | 為什麼是它 |
|---|---|---|---|
| `nomic-embed-text` | embedding | 所有 chunk + query | 768-dim，輕，ollama 直裝 |
| `llama3.2:3b` | router / 分類 | 「這 query 需不需要大 model」、log 分類 | 2GB、快、夠用 |
| `qwen2.5-coder:7b` | code-aware digest | input < 5K token、跟 code 直接相關 | code 訓練扎實 |
| `deepseek-r1:14b` | reasoning digest | input ≥ 5K token 或要跨檔關聯 | 14B 才壓得住長 context 推理 |

**Escalation rule：** `qwen` 跑完如果輸出含 `<<NEED_REASONING>>` token，自動丟給 deepseek 重跑。（v0.1 簡單版可不做，先全部 deepseek。）

## 8. Dogfood Plan

**對象：** Lode 專案（`/Users/lion/Documents/lode/`）

**步驟：**
1. Phase 0 code 寫完 → `cd /Users/lion/Documents/lode && ctx init`
2. 第一週：手動每天 `ctx ask`，記錄哪些查詢有用 / 沒用
3. 第二週：建 ollama cron，每週日跑 `ctx brief --recent 7d` 產 weekly digest
4. 第三週：寫個 Claude session 開工前的 hook，自動把 `ctx brief` 進剪貼簿
5. 第四週：量測 — 比較 ctx 有/無時的 token 使用 + autocompact 觸發次數

**成功標準（G1 驗收）：** Lode session 平均 per-turn context 降 ≥ 60%，autocompact thrashing 一週 ≤ 1 次。

## 9. Open Questions

| # | 問題 | 暫定答案 | 何時要決定 |
|---|---|---|---|
| Q1 | vector store 用 sqlite-vec / chromadb / faiss | sqlite-vec（單檔、無 daemon） | code 開工前 |
| Q2 | chunk 策略 fixed-token vs semantic split | fixed-token 400/50 起跳，後續再調 | code 開工前 |
| Q3 | digest 每次重算 vs cache | cache 7 天 + query hash key | code 開工前 |
| Q4 | per-file digest vs per-topic digest 哪個是 primary | per-topic（更貼近人類問問題的方式） | dogfood 第二週決 |
| Q5 | `.ctx/` 要不要 commit 到 git | config.yaml + digests/ 進 git；index/ + cache/ + memory/ 不進 | v0.1 預設 .gitignore 寫好 |
| Q6 | ollama timeout / 失敗時 fallback 機制 | v0.1：明確報錯不 fallback；v0.2 再考慮降級到 grep | v0.1 ship 前 |
| Q7 | 是否支援非 ollama 後端（lm-studio / mlx） | v0.1 不做，預留 `models.backend` config key | v0.2 |
| Q8 | OSS license 用 MIT 還是 Apache-2.0 | MIT（簡單、最大 adoption），除非要 patent grant 才換 Apache | OSS release 前 |
| Q9 | Cloud sync 預留架構：chunk 加密粒度 per-chunk 還是 per-file | 暫定 per-chunk（newline-delimited JSON 一行一個），便於差異 sync | v1.x cloud 設計時 |
| Q10 | **「ctx」名字已被至少 2 個 OSS project 用，要不要改名** | 待 Rex 決 Path A/B/C（見 [`../competitive_landscape.md`](../competitive_landscape.md)） | **進 code 前必須決** |
| Q11 | **整體定位：standalone OSS CLI vs Lode 的開源 backend** | 推薦 Path B（Lode-led），但 Rex 拍板 | **進 code 前必須決** |
| Q12 | **Kill criteria**：什麼條件下停止 ctx | 建議：dogfood 3 個月後若 Rex 自己沒每天用 → 砍 | spec 凍結前 |

## 10. Out of Scope（明確不做）

- ❌ chat REPL（`ctx chat`）— 不是 chat client
- ❌ 自動寫 commit message — 那是另一個工具
- ❌ code execution / agent loop — ctx 是 context 預處理器
- ❌ 多人協作 / sync — local-first 就是 local-first
- ❌ GUI — Lode 之後當 visual frontend，ctx 本體不做
- ❌ 即時 file watch + 自動 reindex — Phase 0.2 才考慮
